# Бенчмарк холста Doop

Для Doop Dev эталон — системный macOS WebKit. Tauri использует WKWebView, а Chromium служит вторым движком для проверки переносимости результата. Сам бенчмарк измеряет интервалы callback `requestAnimationFrame` по аргументу `time`. Эти интервалы не измеряют момент физического показа кадра.

## Запуск

Нужны установленные зависимости, Bun, Xcode Command Line Tools для WebKit и локальный Chrome/Chromium для Chromium. Перед серией проверьте `vm_stat` и приостановите тяжёлую работу. Запускайте серии последовательно. WKWebView открывает окно 1280×800 CSS px позади остальных окон без активации. Для DPR 2 нужен Retina-дисплей. Chromium по умолчанию headless, с DPR 2. `--headed` на Mac открывает окно Chromium фоновым запуском и использует нативный DPR.

```sh
bun run bench:canvas --engine webkit --scenario all --frames 68 --pairs 3
bun run bench:canvas --engine chromium --scenario all --frames 68 --pairs 3
bun run bench:canvas --base . --candidate . --engine webkit --scenario zoom --pairs 5
bun run bench:canvas --base . --candidate . --engine webkit --scenario pan --pairs 5
bun run bench:canvas --base . --candidate . --engine webkit --scenario drag10 --pairs 5
bun run bench:canvas --engine webkit --scenario zoom-wide --pairs 1 --hud
bun run bench:bundle --base-ref 6d5d1f7b
```

`--engine both` запускает движки по очереди. У `--frames 20|68|200` ожидается 15, 41 или 100 готовых документов соответственно. Остальные оболочки размещены далеко за пределами камеры. В сцене два анимированных SVG и один фрейм размером 800×2200. `--duration` задаёт длину измеряемого жеста в миллисекундах, по умолчанию 3000. У `open` время с начала навигации до готовности видимых документов и двух следующих rAF измеряется в свежей странице. У остальных сценариев перед измерением выполняется прогон на 900 мс, сброс положения и ожидание готовности.

`pan` посылает wheel по оси Y, `zoom` использует Ctrl+wheel для 5,5–10,02%, `zoom-wide` проходит 5–60–5%. Движение задаётся шагами около 20 мс с паузами 40 мс у крайних положений. `drag1` и `drag10` выбирают фреймы через Zustand и отправляют синтетический PointerEvent в заголовок, затем в установленные редактором обработчики `pointermove` и `pointerup`. Alt отключает привязку, а конечные координаты каждого фрейма сверяются с движением указателя.

`--site <dir>` принимает готовый каталог с `tests/fixtures/perfCanvas.html` и `assets/`. `--base` и `--candidate` принимают такие каталоги или рабочие деревья с этим стендом и установленными зависимостями. Каждому варианту выделяется собственный порт на `127.0.0.1`. Одинаковые пути в A/A собираются один раз. Для сохранения готового сайта с метаданными Git используйте:

```sh
bun -e 'import { buildSite } from "./scripts/bench/site"; await buildSite(".", process.argv[1])' /absolute/path/to/site
```

Внешний prebuilt-каталог без `bench-build.json` будет отмечен с неизвестным SHA. Сборка читает только файлы рабочего дерева. Фикстура заменяет WebSocket заглушкой, URL для сохранения позиции фрейма возвращает локальный ответ, а CSP ограничивает сетевые запросы адресом фикстуры. Живая база и сервер приложения в измерении не участвуют.

### Копия реального холста

```sh
bun run bench:canvas --engine both --scenario all --scene /path/to/canvas.json --pairs 1
bun run bench:canvas --engine webkit --scenario zoom --scene /path/to/canvas.json --base /path/to/base --candidate . --pairs 5
```

`--scene` принимает JSON-экспорт с полями `source`, `exportedAt` и `frames`. Храните экспорт вне репозитория. Фикстура загружает его по loopback, помещает фреймы на одну страницу и упорядочивает их по X, Y и ID. Для drag выбираются первые один или десять фреймов в этом порядке. Для внешних стилей, изображений, шрифтов и медиа разрешён HTTPS, CSP оставляет `connect-src 'self'`.

Оба сайта в A/B должны содержать фикстуру с поддержкой `--scene`. Им передаются одинаковые байты экспорта. SHA-256 сверяется между сторонами и с результатом A/A при использовании `--noise`.

Стенд ждёт все оболочки и 1,5 с стабильного состава готовых iframe. На это отведено 90 с после открытия и отдельно после сброса прогрева. Время `open` включает загрузку JSON и ожидание стабильности. На границах замера все смонтированные iframe должны быть готовы. Количество может меняться в ходе прогона и различаться между сторонами A/B. В JSON и сводке записываются размеры каждой выборки документов, дельты swap и средняя нагрузка хоста за 1, 5 и 15 минут.

Для pan и обоих zoom реальной сцены стенд после сброса прогрева ждёт снимки до 8 с и записывает их фактическое число перед измеряемым жестом. `settle.maxMs` берётся из интервалов rAF после последнего обновления камеры до первого кадра, достигшего отметки 600 мс. При отсутствии полного интервала `maxMs` равен `null`. Генератор в zoom и zoom-wide использует отдельную фиксированную траекторию для проверки смены масштаба раскладки.

`--diagnose-snapshots` добавляет в JSON события планировщика, попытки захвата, ошибки ресурсов и результат прямого растра «Главная · 1920». Флаг работает с одним локальным билдом, `--scene` и `--scenario pan`. Диагностические выборки сохраняются среди отклонённых.

## Результаты

Путь по умолчанию — `~/Library/Application Support/Doop Test/bench/<timestamp>-<label>/`. Для реального экспорта к имени добавляется `-real`. `--out` задаёт другой каталог. `result.json` содержит параметры, версии движков, SHA сборок, сырые метрики каждого прогона и причины отклонений. `summary.md` показывает медиану p50, p95 и максимума по принятым прогонам. Доля ≥50 мс рассчитана по всем принятым интервалам вместе. Для `open` главная метрика — медиана времени до полезного кадра, а для остальных — p95 интервалов. Отрицательная дельта B−A означает ускорение. Процентили одного прогона используют ближайший ранг.

Условия отклонения:

- Записи в swap превысили `--max-swapouts` (по умолчанию 0) или чтения превысили `--max-swapins` (по умолчанию 256 страниц). `vm_stat` читается вокруг измеряемого окна, для `open` начальное чтение происходит при запросе HTML. На системах без macOS этот счётчик недоступен, проверка swap применяется только на macOS.
- Фактические минимум, максимум или конечное положение камеры отклонились от сценария более чем на 1 CSS px по X/Y или 0,0001 по zoom. В паре также сравниваются фактические диапазоны, сцена и число шагов камеры. Допустимое расхождение шагов — большее из 5 шагов и 20% от большего результата.
- Замер отличается размером окна, DPR, видимостью документа, числом событий ввода, количеством готовых и смонтированных документов либо конечной позицией перетаскиваемых фреймов. Для жеста нужно от 10 интервалов rAF, а для pan/zoom — хотя бы два шага камеры.

При отклонении повторяется вся пара, максимум два дополнительных раза. Для реальной сцены с `--pairs 1` запускается по одной попытке в каждой серии. Отклонённые попытки сохраняются в JSON. Порядок пар — AB, BA, AB, BA. В A/A порог шума равен максимальному абсолютному Δ среди принятых пар, с минимумом 1 мс. В A/B порог берётся из указанного `--noise path/to/result.json` с подходящей серией A/A или из дополнительной автоматической A/A на базе. `win` или `regression` требуют всех запрошенных валидных пар, минимум трёх, не менее 80% дельт в одну сторону и медианной дельты строго за порогом. При достаточных данных внутри порога выводится `no change`. При нехватке данных вердикт помечается как `insufficient data`.

## HUD и бандл

В dev-сборке включите `?perfHud=1` или запишите `localStorage['doop:perf-hud'] = '1'` и перезагрузите страницу. Для отключения уберите параметр и ключ, затем перезагрузите. Панель обновляет показания четырежды в секунду, считает FPS и коммиты React за 1 с, p95, максимум и длинные кадры за 2 с, число смонтированных и готовых iframe. На фикстуре `--hud` также сохраняет `bench/hud.png`, путь можно сменить через `--screenshot`. Для чистого замера оставьте панель выключенной.

`bench:bundle` строит production в отдельной временной папке и сохраняет `bundle.json` в корне очередного отчёта. `--out` может положить его рядом с результатом холста. Размеры gzip и Brotli вычисляются для каждого JS-файла отдельно. Initial JS включает entry и транзитивные статические импорты с Vite modulepreload. Top 10 берётся из `renderedLength` Rolldown, это вклад модулей до финального сжатия. `--base-ref` строит Git-ревизию с теми же локальными зависимостями, поэтому подходит для сравнения ревизий с совместимыми lockfile.

Быстрые проверки без интеграционного стенда и браузера:

```sh
bun run test --config tests/perf/vitest.config.ts tests/perf/bench.test.ts
```
